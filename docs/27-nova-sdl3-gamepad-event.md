# Nova SDL3 Gamepad semantic event delivery

Test date: 2026-08-08

Device: Retroid Pocket Nova, `kalama`, Snapdragon/Adreno 740

ADB serial: `675a2365`

This is the identity-safe follow-up to [doc 26](26-nova-sdl3-event-input.md).
It opens Valve's shipped ARM64 `libSDL3.so.0` directly, selects the exact
relay-created event path, opens that device through SDL3's Gamepad API, and
observes one injected `BTN_DPAD_DOWN` press/release.

The test is deliberately below Steam's own SDL/Gamepad instance. It proves the
Linux/uinput, Holo `libudev`, non-root access, SDL3 mapping, and semantic SDL3
event path; it does not prove Steam Input or SteamUI navigation.

## Reproducible test

```sh
NOVA_SDL3_GAMEPAD_EVENT_PROBE=1 \
NOVA_INPUT_UDEV_MODE=enabled \
NOVA_INPUT_UDEV_RELAY_TIMEOUT=20000 \
NOVA_SDL3_EVENT_CODE=545 \
NOVA_SDL3_EVENT_TIMEOUT=10000 \
android/nova-lab/deploy-native-steam-input-device-probe.sh
```

The build inputs are generated by the deploy wrapper when missing, or can be
built explicitly:

```sh
android/nova-lab/build-uinput-gamepad-relay.sh
android/nova-lab/build-sdl3-joystick-probe.sh
```

The raw Linux code is 545 (`BTN_DPAD_DOWN`). SDL3 maps the relay device to
the Xbox 360 Gamepad mapping and reports SDL Gamepad button 12 for both the
down and up transitions. The probe also verifies that the event's SDL `which`
instance ID is the ID returned when it opened `/dev/input/event9`.

## Implementation detail that matters

The relay no longer polls and drains the virtual event file descriptor while
Steam/SDL is consuming it. It keeps the descriptor for readiness/self-test,
but leaves event delivery to the actual consumer. This avoids a test helper
stealing events from the process under investigation.

The SDL probe also receives the exact expected path from the device smoke
harness. It matches `/dev/input/event9` before falling back to a name, because
two same-name virtual nodes can coexist after an Android activity or earlier
root helper has exited.

## What remains open

- Steam's own SDL/Gamepad instance must be shown to receive the event.
- Steam Input must translate it into a UI action.
- The Steam Gamepad UI selector must actually move.

The existing native Steam FD and AHardwareBuffer smoke remains useful evidence
for process/session health, but it is not a substitute for those consumer-level
assertions.
